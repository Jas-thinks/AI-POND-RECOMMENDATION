# Workflow

- Does not want commits, pushes, git remote changes, or branch changes made unless explicitly instructed. Confidence: 0.9
- Prefers to review changes before they are committed — "stop after showing me the results so I can review them before committing." Confidence: 0.9
- Prefers that I inspect/understand the existing code and identify the real bottleneck before editing; before editing the frontend wants existing files inspected and the smallest affected set identified, and after editing wants exactly which files were modified plus a summary of the improvements. Confidence: 0.8
- Prefers a final structured report covering files changed, what was changed, apex bottleneck, tests run/results, and remaining risk. Confidence: 0.6
- Prefers a final code review that shows `git diff --stat` / `git diff` of all modified files and confirms git status + that `.env` is not tracked before finishing. Confidence: 0.8
- When committing as instructed, wants commits strictly scoped to the reviewed/intended files only (excluding incidental/untracked session dirs), with a user-specified commit message, no push, and confirmation that the working tree is clean afterwards. Confidence: 0.8
- For substantial changes, wants a smallest-safe implementation plan presented and explicitly confirmed before implementing, especially when the change must preserve existing calculations. Confidence: 0.8
- Wants performance/timing measured and reported before vs after a change (a quantified timing comparison, since slow external calls were a prior bottleneck). Confidence: 0.8
- For a CSS-only frontend redesign, wants the change confined to a single stylesheet and afterwards wants explicit validation: a CSS syntax/parse check, a build (e.g. Vite `npm run build`) to prove the bundle still compiles, a `git diff`/status confirming ONLY the intended file changed (and no JS/backend/API/HTML touched), then a summary of visual improvements and STOP. Confidence: 0.8
- For deleting dead/legacy code, wants the stack first fully verified as disconnected (no references from the active app, tests, scripts, or dependencies), presented for explicit confirmation before removal, and afterwards wants a final reference check (grep) plus git status confirming no dangling references. Wants destructive cleanup to leave the user's in-progress modified/untracked work untouched. Confidence: 0.8
